# Лоадер Violite

Сборка из корня проекта:

```powershell
node build/key-loader.js
node build/key-loader.js --preview
```

`dist/release/Violite.loader.ui.lua` (собирается и `build-release.bat`) — читаемый исходник интерфейса для отдельной обфускации.
По выбранной схеме его обрабатывают в отдельном скрипте Jnkie, скачивают результат
и вставляют обфусцированный код интерфейса в **UI Source** основного скрипта.
Без предварительной обработки вставка этого файла напрямую оставляет UI открытым.
Защищённая сборка основного скрипта размещается отдельно в **Original Code**.
UI ожидает ввод, устанавливает `getgenv().SCRIPT_KEY` и завершается. Проверку ключа
и запуск защищённого кода выполняет Jnkie. Закрытие возвращает управление через
верхнеуровневый `return`, не передавая ключ. REST API-ключ здесь не используется.

Кнопка получения ключа копирует https://jnkie.com/get-key/violite-free.
Другую публичную ссылку можно задать аргументом `--key-url https://…` при сборке.

`dist/dev/Violite.loader.preview.lua` (собирается и `build-dev.bat`) можно запускать через executor/MCP рядом с
основным скриптом: он показывает окно, проверяет формат ввода, но не авторизует,
не меняет `SCRIPT_KEY` и не сохраняет ключ. Повторный запуск не создаёт дубль.

Размер окна — 640×460 с уменьшением под экран. Логотип, шрифты и четыре темы
берутся из `Libraryes/GUI.lua`; при сборке включается только раздел оформления, общая оболочка окна и acrylic-размытие.
При открытии читается `VioCFG/Violite/theme.txt`, как в основном скрипте.
Если файла нет или тема неизвестна, используется Violite.

В рабочем режиме включённая галочка сохраняет последний **введённый**, ещё не
проверенный Jnkie ключ в `VioCFG/Violite/loader-key.txt`. При следующем открытии он
подставляется в поле без автозапуска. Отправка со снятой галочкой очищает ранее
сохранённый ключ. Это обычное локальное хранение, не шифрование.

Авторизацию, неверный/просроченный ключ и отмену необходимо проверить после
загрузки UI Source в Jnkie через его итоговую ссылку запуска. Локальный предпросмотр
не подтверждает эту интеграцию. Серверная проверка версии и управление сессиями
в эту сборку не входят.

Язык окна следует Game Language (`LocalizationService.RobloxLocaleId`), включая
изменение при открытом окне: русский и английский, для остальных — английский.
Успешное копирование меняет подпись кнопки и подсказку на 5 секунд; повторное
нажатие отсчитывает срок заново. Область под запуском зарезервирована для
ошибок и уведомлений; при открытии она пустая.

Переключатель в нижней строке: `Language: Auto → Ru → En → Auto`. Выбор действует
до закрытия окна; Auto использует Game Language, ручной выбор имеет приоритет.
Кнопки плавно подсвечиваются при наведении и дают цветовой импульс при нажатии.
Повторное нажатие перезапускает импульс; при закрытии tween и таймеры отменяются.

## Схема публикации

1. Исходники проекта хранятся читаемыми. Релизный бандл собирается отдельно от UI.
2. Основной релизный бандл загружается в Original Code основного скрипта Jnkie;
   обфускацию выполняет Jnkie. Dev-сборка для публикации не подходит.
3. UI обрабатывается отдельно. Скачанный результат нужно проверить: это должен
   быть исполняемый интерфейс без предварительного требования ключа второго скрипта.
   URL запуска второго защищённого скрипта не заменяет обфусцированный UI.
4. Результат вставляется в UI Source основного скрипта. Он должен дождаться ввода,
   передать SCRIPT_KEY и завершиться; при закрытии — остановить внешний UI Source.
   После обфускации необходимо отдельно проверить, сохранилось ли это поведение.
5. Финальная проверка выполняется через ссылку основного скрипта: отмена, неверный
   ключ, верный ключ, повторный запуск. Совместимость скачанного артефакта пока
   не проверена — самого файла от Jnkie в проекте ещё нет.

Основание: `D:/Tools/lua/Violite-Docs/09-Не-сделано.md` и
https://docs.jnkie.com/roblox-sdk/inline-ui.md.

Панель по существующей схеме раздаётся Caddy из `/opt/rbxmain/admin-panel`,
доступна через SSH-туннель на порту 8090; systemd-таймер забирает main примерно
раз в 30 секунд. Это доставка статических файлов, а не запуск серверного API.
